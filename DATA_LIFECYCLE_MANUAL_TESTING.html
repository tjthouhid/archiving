TEST-74 — Link organisation email to personal email to create learner record

Linking is not a merge. Org A’s account l@orga.com and Org B’s account l@orgb.com stay separate. The learner adds l@primary.com on one of them. When the other address already belongs to an account, linking asks for one new password. That password is the one used next time, from either email. Org A still sees only l@orga.com. Org B still sees only l@orgb.com.

  1. Create the learner in Org A with l@orga.com, and in Org B with l@orgb.com.
  2. Sign in as the Org A account. On /settings/security, add l@orgb.com and open the verification link.
  3. Set a password and confirm it, then choose Link accounts. Sign out. Sign in with l@orga.com or l@orgb.com and that new password.
  4. As Org A, open the learner. The email is l@orga.com. As Org B, the email is l@orgb.com. Each organisation list shows Linked account under the email, and does not show the other organisation’s email.
  5. On /admin/users/list both people are still separate rows. Under l@orga.com the row says Linked to l@orgb.com. Under l@orgb.com it says Linked to l@orga.com.
  6. Org A archives the learner. Org B can still open them and their Org B courses. On /settings/account the learner still sees Org A as a past employer.
  7. IW unarchives them back to Org A with the same email, choosing Active. The profile shows a past archived period and a new Rehired period. New courses belong to the new period. The old courses stay on the past period.
  8. On /settings/privacy, leave Workplace DNA scores unshared. Org B does not receive a score that also includes Org A. Share Org A’s score with Org B. Org B can then see that shared score. Org A still sees its own score without that share.

Set password — IW admin only

On the IW user list, Set password is on the row menu only when the admin has Set user password. That permission is on the IW Owner role. Another admin role does not see it. The two linked accounts stay two users, so the password changes only the row you open.

  1. Open /admin/users/list as an IW Owner. On a row, choose Set password, enter it twice, and choose Update password.
  2. Sign in as that person with the new password.
  3. Sign in as an admin who is not an IW Owner. Set password is not on the row menu.

TEST-94 — Allow Organisation to be archived from Edit Organisation

1. Users

Tenant users list · /admin/users/list

✅ Do

  • Organisation: Set inactive to pause someone. Set active brings them back.
  • Organisation: Archive hides them from this organisation only, including people already set inactive. Only IW can restore that.
  • IW Archived tab: Unarchive is on the row menu as well as the bulk action.
  • Confirm the Inactive tab count equals the number of rows, including older archived accounts that were soft-deleted.
  • IW: archive one organisation, then unarchive and choose Active or Inactive, plus registrations and certificates.
  • Use Delete on the row only when the record should be anonymised.
  • On the IW Deleted tab, do not look for Delete in bulk Actions. It is removed. The row menu already hides it.

❌ Don’t

  • Don’t expect the organisation to see an Archived or Deleted tab.
  • Don’t expect Archive in one organisation to change another organisation or the personal login.
  • Don’t expect the organisation to undo an archive.
  • Don’t delete a Platform Owner or your own account casually.
  • Don’t expect to delete a user who is already on the Deleted tab.

Tick when done

2. Products

/admin/products/list

✅ Do

  • Use tabs: Active / Inactive / Archived.
  • Select several products and use Set as inactive. On the Inactive tab, Set as active brings them back. That is not Archive.
  • Use Archive only when product should leave the catalogue (soft-delete).
  • Unarchive and choose Active or Inactive.

❌ Don’t

  • Don’t treat Inactive the same as Archived.
  • Don’t hard-delete products (no Erased for products).
  • Don’t assign Inactive or Archived products to new orders.

5. Events / Trainers

/admin/events · /admin/trainers

✅ Do

  • Leave a completed or cancelled event on the Active list until someone archives it.
  • Archive events only when status is completed or cancelled.
  • After archive, confirm a new booking is refused and the learner’s existing booking is still in their history.

❌ Don’t

6. Hold-to-confirm delete (5 seconds)

Any DeleteResourceForm modal · Delete user

✅ Do

  • Press and hold ~5 seconds to confirm destructive actions.
  • Release early to cancel safely.

❌ Don’t

  • Don’t expect a single quick click to delete anymore.
  • Don’t assume Delete is the same as Archive. Delete anonymises.

Tick when done

7. Delete (anonymise — users only)

Row menu → Delete, on organisation users and /admin/users/list

✅ Do

  • Use Delete only when the person should be anonymised.
  • Fill in first name, last name, a reason of at most 200 characters, and the confirmation tick, then hold to confirm.
  • Expect the Deleted tab only for an IW admin with View Deleted users (admin:organisation:deleted_users:view). Open the shell from the row menu. It cannot be recovered or edited.

❌ Don’t

  • Don’t delete products or organisations this way.
  • Don’t expect Delete to be reversible.
  • Don’t use Delete when Inactive or Archive is enough.
