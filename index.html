Data Lifecycle testing guide

Simple view of what you should do and what you must not do when checking Active → Inactive → Archived → Erased. Tick each check as you go.

Branch: feature/user-lifecycle-inactive-archive Updated: 2026-09-30 Source: docs/DATA_LIFECYCLE_MANUAL_TESTING.md
⚠️ Never update the legacy database. Test only on the local/app database.
Active Live and visible. Org + IW can manage in normal lists.
Inactive Hidden from active work. Org can restore users. Products stay in DB (not soft-deleted).
Archived Removed from org restore in most cases. IW can restore. Soft-deleted / restricted.
Erased GDPR anonymise for users only. Irreversible. IW only.
1. UsersTenant + Admin 2. ProductsAdmin catalogue 3. OrganisationsArchive + login 4. CertificatesOrg vs learner 5. Events / TrainersRules 6. Hold delete5 second confirm 7. EraseGDPR

1. Users

Tenant users list · /admin/users/list

✅ Do

  • Use org Archive or Delete/Detach to make a user Inactive for that org only.
  • Check the same user can still use another organisation.
  • Org Unarchive to bring them back to that org.
  • IW Admin: use Archive Selected for platform-wide archive.
  • IW Admin: use Erase Selected (GDPR) only when you mean permanent anonymise.

❌ Don’t

  • Don’t expect org Archive to soft-delete the global user (that was the old bug).
  • Don’t expect org Archive in Org A to break login for Org B.
  • Don’t expect IW Unarchive to auto re-join every organisation.
  • Don’t erase Platform Owner / current admin casually.

Tick when done

2. Products

/admin/products/list

✅ Do

  • Use tabs: Active / Inactive / Archived.
  • Use Set Inactive / Set Active to change availability without soft-delete.
  • Use Archive only when product should leave the catalogue (soft-delete).
  • Unarchive and choose Active or Inactive.

❌ Don’t

  • Don’t treat Inactive the same as Archived.
  • Don’t hard-delete products (no Erased for products).
  • Don’t assign Inactive or Archived products to new orders.

Tick when done

3. Organisations

/admin/organisations/list

✅ Do

  • Archive duplicate / wrong orgs from admin list.
  • Unarchive from Archived tab when needed.
  • Confirm login to an archived org is blocked.

❌ Don’t

  • Don’t hard-delete organisations.
  • Don’t expect users to open an archived org portal.
  • Don’t touch legacy DB while testing.

Tick when done

4. Certificates

/courses/certificates · /courses/my-certificates

✅ Do

  • Org can Archive certificates from active workspace.
  • Learner should still see their own certificates (including archived).
  • IW restores via admin IOSH tools if needed.

❌ Don’t

  • Don’t expect org UI to offer Unarchive on certificates.
  • Don’t hide archived certs from the learner “my certificates” view.

Tick when done

5. Events / Trainers

/admin/events · /admin/trainers

✅ Do

  • Archive events only when status is completed or cancelled.
  • Archive trainer = remove trainer role assignment (user can remain).

❌ Don’t

  • Don’t archive draft/live/in-progress events (should fail).
  • Don’t confuse trainer archive with full user erase.

Tick when done

6. Hold-to-confirm delete (5 seconds)

Any DeleteResourceForm modal · Admin Erase users

✅ Do

  • Press and hold ~5 seconds to confirm destructive actions.
  • Release early to cancel safely.

❌ Don’t

  • Don’t expect a single quick click to delete anymore.
  • Don’t assume Erase is the same as Archive (Erase anonymises).

Tick when done

7. Erase (GDPR — users only)

/admin/users/list → Erase Selected (GDPR)

✅ Do

  • Use only for valid erasure / right-to-be-forgotten cases.
  • Expect name/email anonymised and user soft-deleted.
  • Historical records can keep the user id without PII.

❌ Don’t

  • Don’t erase products or organisations this way (not supported).
  • Don’t expect erase to be reversible.
  • Don’t use erase when Inactive/Archive is enough.

Tick when done
