Data Lifecycle testing guide

Simple view of what you should do and what you must not do when checking Active → Inactive → Archived → Deleted. Tick each check as you go. Start with the changes list.

Branch: feature/user-lifecycle-inactive-archive Updated: 2026-10-06 Source: docs/DATA_LIFECYCLE_MANUAL_TESTING.md
⚠️ Never update the legacy database. Test only on the local/app database.
Active Live and visible. Org + IW can manage in normal lists.
Inactive Still in the organisation. The organisation can set them active again.
Archived Hidden from the organisation. Only IW can restore. One organisation at a time.
Deleted Anonymised record. The word on screen is Delete. Not reversible.

Changes to test (6 Oct 2026)

These are the behaviours that changed. Tick them before the older phase checks.

1. Users

Tenant users list · /admin/users/list

✅ Do

  • Organisation: Set inactive to pause someone. Set active brings them back.
  • Organisation: Archive hides them from this organisation only. Only IW can restore that.
  • Confirm the Inactive tab count equals the number of rows, including older archived accounts that were soft-deleted.
  • IW: archive one organisation, then unarchive and choose Active or Inactive, plus registrations and certificates.
  • Use Delete on the row only when the record should be anonymised.

❌ Don’t

  • Don’t expect the organisation to see an Archived or Deleted tab.
  • Don’t expect Archive in one organisation to change another organisation or the personal login.
  • Don’t expect the organisation to undo an archive.
  • Don’t delete a Platform Owner or your own account casually.

Tick when done

2. Products

/admin/products/list

✅ Do

  • Use tabs: Active / Inactive / Archived.
  • Use Set Inactive / Set Active to change availability without soft-delete.
  • Use Archive only when product should leave the catalogue (soft-delete).
  • Unarchive and choose Active or Inactive.

❌ Don’t

  • Don’t treat Inactive the same as Archived.
  • Don’t hard-delete products (no Erased for products).
  • Don’t assign Inactive or Archived products to new orders.

Tick when done

3. Organisations

/admin/organisations/list

✅ Do

  • Archive duplicate / wrong orgs from admin list.
  • Unarchive from Archived tab when needed.
  • Confirm login to an archived org is blocked.

❌ Don’t

  • Don’t hard-delete organisations.
  • Don’t expect users to open an archived org portal.
  • Don’t touch legacy DB while testing.

Tick when done

4. Certificates

/courses/certificates · /courses/my-certificates

✅ Do

  • Organisation tabs: Active and Inactive.
  • Set inactive is reversible with Set active.
  • Archive warns, then hides the certificate. Only IW sees Archived and can unarchive to active or inactive.
  • Confirm the tab count matches the rows.

❌ Don’t

  • Don’t expect the organisation to see an Archived tab or to undo an archive.
  • Don’t expect a Deleted tab for certificates. That waits for the 6-year job.

Tick when done

5. Events / Trainers

/admin/events · /admin/trainers

✅ Do

  • Archive events only when status is completed or cancelled.
  • Archive trainer = remove trainer role assignment (user can remain).

❌ Don’t

  • Don’t archive draft/live/in-progress events (should fail).
  • Don’t confuse trainer archive with full user erase.

Tick when done

6. Hold-to-confirm delete (5 seconds)

Any DeleteResourceForm modal · Delete user

✅ Do

  • Press and hold ~5 seconds to confirm destructive actions.
  • Release early to cancel safely.

❌ Don’t

  • Don’t expect a single quick click to delete anymore.
  • Don’t assume Delete is the same as Archive. Delete anonymises.

Tick when done

7. Delete (anonymise — users only)

Row menu → Delete, on organisation users and /admin/users/list

✅ Do

  • Use Delete only when the person should be anonymised.
  • Fill in first name, last name, a reason of at most 200 characters, and the confirmation tick, then hold to confirm.
  • Expect the Deleted tab to show the anonymised shell. IW can still see that shell.

❌ Don’t

  • Don’t delete products or organisations this way.
  • Don’t expect Delete to be reversible.
  • Don’t use Delete when Inactive or Archive is enough.

Tick when done
